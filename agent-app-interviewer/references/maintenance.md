# 题库维护

仅在扩充资料、修订题卡或发布新版本时读取。根据实际维护目标确定资料范围与工作量，不要求固定周期或最低新增数量。

## 来源核验与去重

- 默认围绕国内校招／实习的Agent、智能体、AI应用开发和RAG岗位，按目标岗位补充其他方向。
- 岗位优先招聘官网，面经优先作者原帖。记录来源链接、发布或面试日期、访问日期、读取范围及岗位状态；历史样本明确标注，页面可读不等于仍有招聘名额。
- 先按链接、岗位编号、作者和事件去重；转载、汇编及原帖不重复计为独立证据。去除追踪参数时保留决定内容或岗位的查询参数。
- 只有摘要或正文不可读的网页保留为L类线索，不支撑题卡评价。面经是作者自述，不能直接当作招聘公司的标准答案或考查频率统计。
- 技术结论核对适用版本的官方资料。无法确认的细节标注限制，不凭印象补造依据。

## 更新题卡

保留历史J/I/C/L/T/D来源编号与Q题号。相同考点优先完善已有题卡；实质新增考点从最大Q编号后追加，不因换一种问法重复建题。

每张题卡应包含考察点、来源、必要证据、合理替代方案、追问触发条件、停止条件和复练变体。`technical_source_ids`仅引用T类官方技术资料，缺少依据时可为空；官方来源只支持其注明的范围。

参考回答可放在非空的`reference_answer`列表中，保留适用条件与替代方案。它是可行路径，不是唯一答案；严格模拟时隐藏，不按关键词机械判分。个人话术、项目指标和产品偏好不能直接转为候选人经历或通用评价标准。

用户PDF按D类单独记数：记录文件名、SHA-256、总页数、选读页和读取限制，`url`使用`urn:sha256:<摘要>`。引用文档的题卡在`document_evidence`中给出`source_id`及物理页码`pages`，不伪造网页链接。示例见 [文档选读与面经摘编](pdf-import-notes.md)。原PDF、全文提取、密钥和个人资料不加入技能包。

同步来源分类数量、题卡索引及README与入口中的数量。`snapshot_date`保留初始快照日期，`updated_at`记录本次维护日期，各来源的`checked_at`记录实际核验时间。

## 校验

在仓库根目录运行，工具仅依赖Python 3.10+标准库：

```sh
python agent-app-interviewer/scripts/validate_bank.py
python -m unittest discover -s agent-app-interviewer/scripts/tests -v
```

可用`--baseline <上一版本技能目录>`检查历史编号保留情况；用`--archive <仓库副本ZIP>`核对分发文件。检查包括题卡字段、编号、来源引用、文档页码、索引、分类数量与本地链接。脚本不能代替原文核验，以及逐题检查追问是否对应当前考点。

调整面试行为或选题路由时，用虚构材料检查：一次一问、缺少材料时不假设个人经历、遵守追问预算、用户要求结束时立即复盘。普通资料补充不随意重写会话规则。

## 提交与发布

修改前比较本地文件、上次发布基线与远端最新内容，保留其他维护者的改动；同一文件有冲突时先解决，不直接覆盖。只提交可分发的技能、文档与校验工具，本地研究笔记、状态、缓存和凭据保持忽略。

检查通过后提交简短变更说明；没有有效变化时不制造空提交。同步后重新读取固定提交的文件或下载仓库副本核对内容，并记录实际提交链接。部分上传、登录失败或校验失败应如实报告，不能标记为发布完成。

可选的`weekly_state.py`仅记录本地维护轮次，不发起网络操作或创建定时任务。使用时可通过`--config`提供本地JSON设置，字段为`weekday`（0—6）、`hour`（0—23）、`utc_offset_hours`和可选的`repository`（owner/repository）；未配置时采用UTC周一零点。个人设置与运行状态应留在被忽略的`research/`目录，不随仓库分发。
