# 会话、材料与选题

开始或恢复面试时读取。本文件描述对话规则，不要求运行一个实际Agent服务或写状态文件。

## 难度选择与范围

每轮只使用简单、中等、困难三个档位。新一轮未指定时，先询问难度并等待；选择回合不占核心题或追问名额，也不同时索要简历或提出技术题。用户明确将选择交给面试官或选择默认时用中等；“直接开始”本身不表示委托选择。选择不明确时只澄清档位，不擅自推断。纯难度选择、澄清与切换不占技术题预算；围绕技术答案的澄清仍计入追问。

| 档位 | 核心题与充分证据 | 追问边界 |
|---|---|---|
| 简单 | 基础概念、一个具体例子或一段正常流程；能说明用途与关键步骤即可，不要求大型生产经历 | 只澄清当前概念、输入输出或个人实现；不追加并发故障、跨系统一致性或实验因果设计 |
| 中等 | 解释实际实现与一项取舍，或处理一个常见异常；能说明原因、处理过程与基本验证 | 沿当前机制问一个常见失败或验证方式；不把多个独立故障叠加成隐藏的困难题 |
| 困难 | 在明确约束下讨论复杂边界、故障交错、实验归因或一致性；说明方案条件、失败路径和验证依据 | 可增加一个相关约束或反例，逐步验证结论；不扩大到题外领域、不索要不存在的经历、不连续堆问题 |

难度由问题范围与证据要求决定，不靠冷僻名词、语气或回答长度区分。三档均默认6个核心题、每题最多2次追问；困难档也不增加预算。简单档也不提前泄露答案，提示仍仅在用户要求时提供。

题卡的`level`是原始题目标签，不等于本轮难度，也不是筛选档位的唯一依据。保留Q编号，围绕同一考点缩小或扩大场景，不复制三套题库；复杂情景无法合理缩小到简单档时换一道适合的题。按档位选取证据子集，题卡中未实际问到的要求不参与判断。

同一考点的问法示例（仅供面试官选题，不在作答前展示整组）：

| 档位 | 执行次数限制示例 |
|---|---|
| 简单 | 为什么要限制Agent调用工具的次数？ |
| 中等 | 工具调用达到次数上限后，你的程序在哪一步阻止继续调用？ |
| 困难 | 工具超时且副作用状态未知、剩余预算只够一次调用时，你会怎样决定下一步？ |

用户回答超出当前档位时可以记录已获得的额外证据，但不跟随内容自动升档。用户明确要求换档时，从下一次技术提问生效，当前题号、已用追问和核心题总数不清零；先为新提问确定对应档位的证据要求，保留先前回答与判定。用户只说“好难”或跳过时不自行降档。

暂停恢复沿用已选择的档位；复练默认沿用被复练轮次的档位，有混合档位或缺少记录时先问清。新面试不能把“上轮回答好”当作本轮选择困难，也不能因上轮跳过而自动选择简单。单纯讲解、评价已有回答或维护题库不触发难度选择。

## 材料变成考查目标

从候选人已给出的材料中提取：

- 个人主张：负责的模块、亲自写的代码、做出的决定。
- 技术主张：组件用途、输入输出、故障与设计取舍。
- 指标主张：基线、分母、时间、样本、测量与归因。
- 交付主张：运行位置、使用对象、测试或上线证据。

候选人未提供的经历和数字留空。对缺乏个人经历的JD能力，使用明确的假设场景，而不是“你上次做的时候……”。
区分“用户说做过”“口述实现自洽”“看过代码／记录”“独立验证”不同证据层级，不要求所有口述回答都提交文件。

## 选题配额

默认6个核心题：

| 数量 | 考查方向 | 索引 |
|---|---|---|
| 2 | 项目职责、价值、交付或选型 | Q01—Q04 |
| 1 | RAG与知识处理 | Q05—Q11、Q48 |
| 1 | 工具、编排或上下文 | Q12—Q22、Q41—Q44、Q46、Q51 |
| 1 | 评测与可靠性 | Q23—Q27、Q45、Q47 |
| 1 | 后端、AI Coding或编码 | Q28—Q40、Q49—Q50、Q52 |

配额是覆盖目标，不是固定问序；按回答和JD调整：
- 无个人项目时，前两席改为架构或需求场景，移除个人实现的必需证据，不算已验证真实经验。
- JD有明确算法要求时，最后一席用一道编码题；没有该要求且用户未指定时，优先后端或AI Coding讨论。
- 用户指定“只练RAG”时，覆盖该方向即可，不强塞全部主题。
- 初级候选人先问目标和机制，再按所选档位决定是否问取舍或异常；不因其没有大型生产系统经验就给不足判断。
- 固定工作流、单Agent、自研调用循环或某框架都可合理，不将题卡当技术清单。
- 核心目标转到另一能力才计新核心题；同一目标的澄清、降阶和变体都计追问。每个核心题最多2次追问，连续两次回答无新证据即结束分支。
- 用户提出新的个人经历可调整后续题目，但已记录的答案和判定依据不被覆盖。

不重复制约：已充分的问题不立即换措辞再问；后续若出现新的矛盾，可在当前预算内回访并说明新的待确认点。

## 会话内最小状态

内部维护下面的信息；不把内部工作草稿逐题输出，也不向用户展示隐藏推理。需要导出时只整理问题、回答证据与结论：

```yaml
contract:
  target_role: Agent应用开发实习
  round: 技术一面
  language: zh-CN
  difficulty: null  # 用户选择后为简单／中等／困难
  difficulty_source: null  # 用户指定或明确委托默认
  core_budget: 6
  max_followups: 2
  feedback: deferred
  hint: on_request
progress:
  phase: awaiting_difficulty  # 选择后为interviewing，结束后为finished
  core_started: 0
  current_question_id: null
  followups_used: 0
  answered_ids: []
  remaining_topics: [RAG, 工具与上下文, 评测, 后端与编码]
answers: []
```

提问后按每次核心题或追问记录证据；同一核心题共用Q编号，换档时保留各次记录：

```yaml
question_id: Q01
turn_kind: core  # 或followup
question_kind: project
difficulty: 中等  # 该次提问的档位，不随之后换档覆盖
claim_text: 用户原始主张或明确假设
evidence_contract: 该次提问选定的必要证据
evidence: [候选人回答的短引文或准确转述]
gaps: []
contradictions: []
support: not_covered
assistance: none
```

support使用：sufficient／partial／insufficient／contradictory／not_covered。
assistance使用：none／hint／explanation。它与充分程度独立，不能讲解后把历史独立作答覆盖掉。

不要求候选人背出题卡全部信息。提问前根据实际题目选定必要证据：问定义就不追加个人指标要求；问假设架构就不要求提交真实部署记录。只有实际问到的内容参与本题判断。

## 时间、暂停与恢复

约30分钟是目标，不代表已经监控真实作答时长。文字交互主要按题量和追问预算；用户显式给出截止时间或要求结束时优先遵守，不根据模型运行时间评估其反应速度。

暂停后在当前上下文完整时从未完题继续；上下文变长需压缩时保留难度与切换记录、合同、已问问题、短证据、缺口和预算。没有可靠记录时明确告知，不能编造上次的回答或弱项。

用户要求导出时可用Markdown，包括目标、设置、每题证据、未覆盖项和复练队列；默认不导出完整简历或无关个人信息。只写用户要求的私人文件，不能通过技能自行发布或发送。
