# 个人面经选题

在用户提供自己的面经，或本地已启用个人配置时读取。这里只定义可复用的选题方式；原始文档、个人项目细节、反馈和练习记录保存在用户私人位置，不随技能分发。

## 加载与材料边界

优先使用本轮明确给出的文件或配置。没有指定时，可检查当前工作区的 `research/personal-interviews/profile.json`；若当前就在本技能目录，可再检查其父工作区的同一路径。只查这些明确位置，不遍历其他目录寻找个人信息。配置不存在、关闭或不可读时使用普通选题规则；不可读时说明本轮未加载，不假装记得旧面经。

配置中的文件路径相对于配置所在目录。最小配置可包含：

```json
{
  "version": 1,
  "enabled": true,
  "selection": {"personal_priority": "high", "fixed_personal_core_count": null},
  "card_files": ["cards.json"],
  "practice_focus": ["解释设计理由和方案取舍"]
}
```

`high`表示相关性和档位相当时优先参考，不是保证出现的数量或概率。仅在当前用户使用其配置时生效，不能把一个人的偏好套给其他候选人。用户临时指定的方向、难度、题量和优先级高于配置；用户要求暂停个人优先时，本轮用普通选题即可。

先读配置和题卡概要，只加载当前相关的题卡与原文段落；无需为了开场读完个人原文。严格模拟不向候选人提前展示参考答案、评价要点和全部题目。

## 选题与追问

将真实原题归并为独立能力目标，映射到已有Q题卡；本地个人题可用P编号保留原题与变体。相同考点不因改写或来自多个来源而增加题量。个人题映射多张Q卡时也只计当前实际考查的一个核心目标。

先满足本轮岗位与用户方向，再在当前档位适合的候选题中优先个人原题及相关复练变体；同时补充岗位必需、尚未覆盖的能力。没有固定个人题数、最低占比或“本轮必须问完”的主题清单。避免每轮照抄同一套问题；有可见历史时，优先未覆盖或需要复练的不同场景，已充分的题不立即换措辞重问。

重点可落在用户复盘中明确提出的问题，例如决策理由、真实个人动作、取舍和验证依据。只有实际回答暴露了缺口，才选择相应追问；历史评价本身不构成当前答错的证据。简单档只要求概念、例子或正常流程，中等和困难档按 [会话规则](session.md) 逐步展开，不因个人答案详细就默认困难。

每回合仍只问一题；全部个人题与通用题共享核心题预算，每个核心题最多两次追问。用户跳过、要提示或结束时沿用原有规则；追问及近似变体不能另算个人核心题来扩大预算。

## 原文、答案与证据

导入时区分以下内容，不能混为公司标准或个人已完成事实：

- 真实原题：保留用户原文及定位，可影响选题；公司名称不构成评分依据。
- 用户转述的面试反馈：提示需要观察的表达或知识维度，不直接形成能力结论。
- 事后补充答案：用于备课、应请求讲解和复盘，不计入本轮独立作答。
- 文档自述的实现与验证：保留日期、版本及核验层级，不声称已经独立检查代码或重跑测试。
- 拟议改进：可以出明确假设的设计题，不能用“你已经实现的……”引导虚构经历。

以文件摘要及段落、表格或实际页码定位来源；DOCX段落序号不能冒充物理页码。技术依据优先复用映射Q卡的官方来源并核对版本；个人稿与官方资料冲突或版本不明时，暂缓该细节判断。提高个人面经权重不意味着必须认可其中每个技术结论。

## 后续补充与分发

新个人面经先按文件摘要、原题与事件去重；相同考点补入已有P卡，实质新目标才增加P编号。保留旧编号、原题、来源定位，以及不同日期的实现边界；较新的自述不自动覆盖已核验记录。只补充当前使用需要的资料，不把每次练习回答自动写入文件。

个人材料与配置保存在被忽略的私人目录。公开技能只携带这份通用规则；不把本地路径、雇主信息、个人反馈、原文或完整抽取加入公开来源账本、题卡或分发包。若用户另行要求公开，先确定具体公开范围；本地使用授权不代表发布授权。
