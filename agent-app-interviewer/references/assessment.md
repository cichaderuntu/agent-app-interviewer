# 证据评价、复盘与复练

## 提问前的证据标准

从题卡挑选本题真正考查的2—3项必要证据，并按候选人级别和题型调整。只在内部记录简明标准，不输出隐藏推理或全套评分树。

- 项目题：个人范围、具体机制或取舍、相应验证。
- 基础题：概念正确，能用一个适用例子解释边界。
- 场景题：约束清楚，方案自洽，考虑关键失败及验证。
- 编码题：题意和接口明确，行为正确，处理边界，说明适用复杂度。

题卡证据不是厂商标准。不能等看到答案后再添加一个未问过的要求判其不足。问题本身含糊或技术依据不明时先澄清；必要时废弃此项判定，说明原因。

## 评价状态

| 内部值 | 面向用户的状态 | 依据 |
|---|---|---|
| sufficient | 回答充分 | 实际问到的必要证据已支持，无未解决的实质错误 |
| partial | 部分充分 | 有有效内容，仍有明确缺口，或关键事实有待核验 |
| insufficient | 证据不足 | 追问后仍不能说明最低机制／事实，或核心解释有明确错误 |
| contradictory | 存在未解决矛盾 | 与原文或前文出现冲突，经澄清尚未消除 |
| not_covered | 未覆盖 | 没有取得可评价的作答，不等于不懂 |

“证据不足”用于当前回答，不能直接升级为“这个人不会做”或“项目造假”。个人经历只能说“回答支持／未支持该主张”，不能声称已核实其真实发生。

- 跳过未作答 → 未覆盖；跳过前有部分回答 → 保留已得证据，未答部分注明。
- “不会”且没有最低说明 → 证据不足；不连续羞辱或反复问同一题。
- 提示或讲解 → 保留原独立作答证据，另标辅助后表现；不做无辅助能力结论。
- 合理替代实现 → 按约束评价，不按关键词命中打分。
- 技术细节未核验 → 暂不判该细节错误；说明本轮限制，不把不确定变成候选人的错误。
- 代码未执行 → 可评价静态逻辑、边界和复杂度，但明确没有运行验证；不宣称通过测试。

## 追问例子

这些仅说明如何选择下一问，不在候选人回答前展示。

**候选人说**：“做了混合检索，准确率提高20%。”
内部先记录缺基线、指标定义和样本；只问一个最关键缺口：“这里的准确率如何计算？”不一次列出五个追问，也不替其补实验数据。

**候选人说**：“这个小任务用固定流程，模型只负责分类，失败就退出。”
若能解释约束和取舍，不因未用ReAct或多Agent判错；可问一个扩大场景的变体，不能偷偷把使用复杂框架设成通过条件。

**候选人说**：“我实现了整个系统”，随后说“检索由同事实现。”
先问“你说整个系统，具体包含哪些由你实现的部分？”只有澄清后仍冲突才记未解决矛盾。

## 严格模拟的可见输出

正常回合只用自然承接语和一个问题，不显示分数、完整缺口清单或参考答案。可以重复用户刚说的事实定位下一问；不能写“正确答案是……你再补一下……”。
用户主动请求评价、提示或讲解时才提供对应帮助；记录辅助，之后按其继续意向恢复模拟。

## 结束复盘格式

1. **范围**：目标岗位、实际问过的核心题／追问数、是否含提示或讲解；不要把预算当实测时长。
2. **能力与证据表**：能力、状态、回答短引文／准确转述、关键缺口。引用实际回答，不编造候选人用语。
3. **优先改进**：最多3项，区分补知识、补项目事实、补验证、改表达；每项给一个能完成的动作和检查方式。
4. **未覆盖与限制**：哪些JD能力没问、哪些细节未核验、代码有无执行、受辅助情况。
5. **复练建议**：给薄弱点相应变体的训练目标。结束时不要求用户继续作答，等待其主动复练。

不补造精确总分、市场百分位、录用概率、公司通过结论。若用户要求分数，说明本技能使用按证据分级，并给出上述表；不把无校准数字当客观评价。

## 复练

有会话证据时，从partial、insufficient或未解决矛盾选择最多3个核心题；not_covered只有用户希望补全时再选。使用题卡retry_variant或针对缺口生成的新场景，不能原样再问并把背熟视为能力改善。

提问前保留旧缺口，回答后比较是否提供新证据；标明是否仍依赖提示。没有历史或可用小结时明确说明，不能编造历史弱项。候选人说“直接重新开始”时用默认新面试，不反复索要不存在的旧记录。
